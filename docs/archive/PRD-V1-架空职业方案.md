## 1. 项目结论

### 1.1 游戏名称

**暂定正式名称：《一纸履历》**

名称含义：玩家从一张空白履历开始，在虚构城市中经历工作、家庭、健康与公共事务抉择，最终形成独一无二的人生档案。

选择理由：

- 四个汉字，容易记忆，能表达“选择塑造人生”的核心玩法。
- 不使用真实党政机关、行政级别、国家机关标识或“人民、国家、监察、反腐”等个人主体服务名称的高风险词。
- 截至 2026-09-08 的公开网页、TapTap 和国家新闻出版署公开信息初筛中，未发现同名游戏。
- 与参考产品《我太想进步了》在名称、世界观、表达方式上有明显区隔。

名称仍须满足三个上线条件：

1. 在微信小游戏后台确认名称可注册；
2. 委托专业机构或通过官方渠道完成商标相同及近似检索；
3. 软著、平台登记、备案或审批材料中的游戏名称保持一致。若任一环节冲突，启用备选名《此生履历》或《履历未完》，并重新完成全部检索。

### 1.2 一句话产品定义

一款发生在**完全虚构城市**中的文字选择型职业人生模拟游戏：玩家在有限时间和资源下处理公共事务与个人生活，通过可解释的评价体系改变岗位、关系和人生结局。

### 1.3 产品边界

本项目借鉴的是“年度推进、事件选择、多属性成长、多结局”这一通用玩法类型，不复制任何现有游戏的文案、事件、数值、界面、角色、图标、音效、代码或宣传材料。

首发版不是现实公务员考试工具，不模拟真实党政机关运行，不影射现实人物和事件，不提供钻营、行贿、违法获利等可操作性方法。

## 2. 上线与合规总原则

“开发完成”不等于“可以上线”。本项目设两道独立验收：

- **产品验收**：玩法、内容、性能和数据达到 MVP 标准；
- **发布验收**：平台资质、APP 备案、游戏相关备案或审批、未成年人保护、隐私、广告、软著与知识产权要求全部满足。

任何一项发布材料不明确时，只能保留为内部体验版，不公开运营、不接广告、不通过改类目、套壳或先上后改规避审核。平台审核通过也不能代替法律法规要求的行政许可或备案。

### 2.1 推荐主体与商业路线

个人开发者的首发路线：

- 产品类型：微信小游戏，而不是普通工具类小程序套壳；
- 收费方式：首发不开放虚拟支付、会员、抽卡、道具充值；
- 变现方式：仅在平台允许、流量门槛满足且广告能力获批后接入平台广告；
- 数据方式：本地存档优先，云端只保存维持游戏服务所必需的数据；
- 后续若要充值、联运或扩大商业化：先成立或接入合格企业主体，并根据届时要求取得出版、运营、网络文化、增值电信等所需资质，不以个人主体强行上线。

> 个人主体能否以广告模式发布本作、具体需要哪些材料，以提交时微信后台、属地通信管理部门、新闻出版主管部门的书面要求为准。规则可能更新，开发前与提交前各复核一次。

### 2.2 发布合规闸门

| 闸门 | 通过标准 | 未通过时处理 |
|---|---|---|
| G0 主体与类目 | 微信后台明确允许当前个人主体创建并发布该类小游戏 | 不发布；评估合格企业或出版运营合作方 |
| G1 名称与知识产权 | 名称可用，完成近似商标检索；软著权属清晰；无第三方素材侵权 | 更名、替换素材或补齐授权 |
| G2 出版与游戏要求 | 已取得主管部门和平台要求的全部审批、备案或证明文件 | 只做内部原型，不公开运营 |
| G3 APP 备案 | 通过平台提交并取得所需备案编号，按要求展示 | 不提供互联网信息服务 |
| G4 内容审核 | 自审清单全通过，敏感内容经专业人员复核 | 删除或改写，不以隐藏入口绕过审核 |
| G5 未成年人保护 | 年龄提示、实名和防沉迷能力按现行要求正确接入 | 不上线 |
| G6 隐私与安全 | 隐私政策、收集清单、授权时机、删除与投诉渠道齐全 | 停止收集或补齐机制 |
| G7 广告 | 广告位、频率、素材和未成年人规则全部满足平台政策 | 关闭广告，先以无广告版运行 |

## 3. 用户与需求

### 3.1 目标用户

- 18—40 岁，喜欢人生模拟、文字选择和多结局内容的微信用户；
- 单次可投入 10—30 分钟，偏好随开随玩的轻量游戏；
- 希望选择产生真实后果，而不是单纯依靠随机数或反复看广告。

建议内容年龄提示为 **12+**，最终以正式内容审核和主管要求为准。产品设计以成年人为主要用户，但不因此免除未成年人保护义务。

### 3.2 已验证的同类产品痛点

公开玩家反馈中常见的问题包括：不同阶段重复同一事件、晋升过度随机、广告收益过低且不透明、高岗位仍处理低阶段事务、薪资与年龄变化缺乏可信度、后期内容浅和重复。

《一纸履历》的对应解法：

- 各岗位拥有独立事件池，跨阶段重复率设上限；
- 评价结果可解释，随机因素不超过晋升评价权重的 15%；
- 广告只换取明确、即时且非必需的便利，不出售隐藏概率；
- 收入、健康、家庭和退休随服务年限联动，并明确声明均为虚构数值；
- 高岗位事件从“亲自处理”转为“资源配置、协调与承担后果”。

## 4. 游戏目标与非目标

### 4.1 产品目标

- 让玩家在 30 秒内理解一次选择会影响哪些指标；
- 一局 18—30 分钟，能够完整经历一次职业人生；
- 同一玩家前三局能明显感受到不同事件、路径和结局；
- 每个关键晋升或转岗结果都能查看原因；
- 用可持续的新事件包提高复玩，而非用强制广告拖延流程。

### 4.2 首发版不做

- 不做真实地名、真实机关、真实领导或现实政治事件；
- 不使用国家机关名称、党徽国徽、正式公章、警用标识或仿官方通知；
- 不做玩家聊天、排行榜、工会、UGC 和陌生人社交；
- 不做充值、会员、付费抽卡、现金红包、兑换和玩家交易；
- 不做需要采集手机号、定位、通讯录、身份证照片或人脸的数据功能；
- 不做“考试上岸”“仕途指导”等现实效果承诺；
- 不在首发版使用生成式 AI 实时生成剧情，避免内容不可控和额外合规风险。

## 5. 世界观与表达规则

### 5.1 世界观

故事发生在架空的“澄川市”。所有地名、机构、岗位、人物和政策均为虚构。

玩家进入“城市事务服务体系”，从基层事务助理起步。职业阶梯使用原创通用名称：

1. 事务助理
2. 项目专员
3. 项目主管
4. 部门负责人
5. 片区协调人
6. 城市事务负责人
7. 城市发展顾问
8. 公共事务总协调人

这些称谓不对应现实行政级别，开始游戏和帮助页持续展示“纯属虚构，不构成现实制度说明”。

### 5.2 内容价值边界

- 困难选择可以没有完美答案，但不能把违法、腐败、欺诈塑造成高收益最优解；
- 若出现利益输送、泄密、滥权等情节，只能以风险识别、拒绝、调查和承担后果为中心，不描述可复制的实施步骤；
- 不污名化具体职业、地区、民族、性别、疾病或社会群体；
- 灾害、伤病和家庭冲突不做猎奇画面，不利用玩家恐惧诱导看广告；
- 角色姓名使用原创虚构名称，禁止影射现实人物；
- 虚构收入、保险和退休机制不得包装成现实政策信息。

## 6. 核心玩法

### 6.1 单局循环

```text
选择出身特质 → 入职 → 年度工作事件 → 个人生活事件
→ 资源结算 → 年度评价 → 晋升/转岗/留任 → 下一年度
→ 退休、离任或特殊结局 → 生成人生履历卡
```

### 6.2 单局结构

- 初始选择：3 个成长背景，每个提供 1 个优势和 1 个代价；
- 时间跨度：最多 24 个服务年度；
- 每年事件：1 个工作事件 + 1 个生活事件；关键年份增加 1 个城市事件；
- 每个事件：情境说明、2—3 个选择、即时影响、延迟后果；
- 年度结算：展示属性变化、未解决事项和评价依据；
- 结束条件：正常退休、主动离任、健康归零、廉正评价失败、家庭线结束或隐藏结局。

### 6.3 六项核心属性

| 属性 | 含义 | 归零或过高的影响 |
|---|---|---|
| 能力 | 学习、判断和执行能力 | 过低会限制复杂岗位 |
| 实绩 | 事务完成质量和长期成果 | 晋升的主要公开依据 |
| 信任 | 市民与同事对玩家的信任 | 影响协作和部分结局 |
| 廉正 | 守规、公开与利益冲突管理 | 过低触发调查与离任线 |
| 家庭 | 陪伴、关系和生活稳定度 | 过低触发家庭危机 |
| 健康 | 身体与心理负荷 | 归零结束本局 |

不设置“金钱可以买晋升”的机制。个人资产只来自虚构的合法收入、住房与日常支出模型，用于人生结算，不可兑换或交易。

### 6.4 晋升与转岗

晋升评分：

```text
公开评分 = 实绩 35% + 能力 20% + 信任 15% + 廉正 20% + 岗位匹配 10%
最终结果 = 公开评分 + 已披露的情节修正 + 不超过 15% 的随机波动
```

规则：

- 每次结果页必须显示各项得分、未满足条件和随机波动值；
- 晋升还需满足实绩最低值（逐级 45、48、52、56、60、64、68）及廉正最低值（逐级 45、50、55、60、65、70、75）；条件在选项中的岗位说明提前公开；
- 岗位不同，权重可小幅变化，但变化须在申请岗位前展示；
- 未晋升不清空累计进度；
- 广告不能直接提高晋升概率，只能允许玩家查看一次更详细的原因或在结算前重选一个非关键选择；
- 高岗位调用专属事件池，不能反复出现低岗位的执行型事务。

### 6.5 事件系统

每条事件包含：

- 唯一 ID、标题、正文、所属岗位、年度区间、触发条件；
- 2—3 个选项及即时属性变化；
- 1—3 年后的延迟结果；
- 互斥标签、前置事件和冷却期；
- 内容风险标签和审校记录；
- 版本号，便于上线后追踪修改。

MVP 内容量：

- 工作事件 96 条，每个岗位至少 12 条；
- 生活事件 36 条；
- 城市长线事件 18 条，组成 6 条三阶段故事链；
- 隐藏事件 10 条；
- 结局 12 个；
- 首三局的重复普通事件比例低于 30%。

### 6.6 结局与复玩

结局由岗位、六项属性、关键标签和故事链共同决定，包括平稳生活、专业坚守、城市改善、家庭优先、健康退场、失去信任等方向。

结算页生成“人生履历卡”，只展示虚构经历、选择风格和结局。分享必须由玩家主动触发，不以“分享给群才可继续”或虚假奖励诱导传播。

## 7. 页面与交互

### 7.1 页面清单

1. 启动页：游戏名、年龄提示、备案与著作权信息入口；
2. 首次告知页：虚构声明、隐私摘要、用户协议；
3. 首页：开始、继续、履历册、设置、规则说明；
4. 开局页：背景选择与属性预览；
5. 主游戏页：年度、岗位、六项属性、事件卡、选项；
6. 年度报告页：变化原因、长线事项、岗位机会；
7. 履历页：历年岗位、重大选择和已解锁结局；
8. 结局页：结局文本、统计、履历卡、再来一局；
9. 设置页：声音、字号、隐私、账号数据删除、客服与投诉。

### 7.2 视觉方向

采用“现代城市工作手账”风格：青绿色城市线稿、暖白卡片、荧光标记笔式重点、简洁无衬线字体。

禁止使用参考产品的版式、配色、卡片比例、图标位置、字体组合和信息层级。不得使用仿政府公文、红头文件、正式印章或国家机关视觉元素。

### 7.3 易用性

- 正文字号不低于 30px 等效显示，主要点击区不小于 88×88px；
- 属性变化同时使用文字和符号，不只依赖红绿色；
- 关键选择提供二次确认，但普通选择保持单击流畅；
- 支持静音、震动关闭和大字号模式；
- 低端设备从启动到首页目标小于 3 秒，事件切换无明显卡顿。

## 8. 商业化设计

### 8.1 首发广告位

只使用玩家主动选择的激励视频：

- 每局最多 1 次“回看并重选普通事件”；
- 每局最多 1 次“健康危机缓冲”，且不能用于规避廉正或违法后果；
- 结局后可看 1 次广告解锁一条纯外观履历卡边框；
- 每日激励视频总上限 5 次。

不在首次 3 分钟、事件选项中间、隐私授权前和未成年人限制时段强插广告。首发不使用开屏广告；插屏广告默认关闭，只有在完整数据证明不伤害体验并通过合规复审后才评估。

### 8.2 广告合规要求

- 仅使用微信允许的官方广告能力，不自行接不明联盟 SDK；
- 广告必须明确标识，不伪装成系统通知或游戏选项；
- 对广告素材建立巡检和投诉流程，发现赌博、色情、诈骗、虚假医疗或其他违法违规内容立即下线并申诉；
- 不向未成年人定向展示不适龄广告，不用连续失败、倒计时恐吓等方式诱导观看；
- 任何收益预测都以实际获批广告位、活跃用户、填充率和 eCPM 为准，PRD 不承诺固定收入。

## 9. 技术方案

### 9.1 推荐技术栈

- 客户端：Cocos Creator 3.x + TypeScript，构建目标为微信小游戏；
- UI：项目内原创组件和矢量线稿，不引入来源不明模板；
- 配置：JSON 事件库 + TypeScript Schema 校验；
- 存档：本地缓存为主，微信云开发只用于可选云存档和合规日志；
- 版本管理：Git；发布版打 Tag，并保存审核对应的代码、内容和素材快照；
- 监控：崩溃、加载失败和匿名玩法漏斗；不接入非必要第三方追踪 SDK。

### 9.2 数据结构示例

```ts
type EventCard = {
  id: string;
  title: string;
  body: string;
  roleLevels: number[];
  yearRange: [number, number];
  prerequisites: string[];
  cooldownYears: number;
  choices: Choice[];
  delayedEffects: DelayedEffect[];
  complianceTags: string[];
  reviewStatus: "draft" | "reviewed" | "approved";
  contentVersion: number;
};
```

### 9.3 安全要求

- 云函数校验所有会影响云存档和运营统计的参数；
- 不在客户端写入云环境密钥、管理员口令或未公开接口；
- 依赖锁定版本并做许可证与漏洞检查；
- 日志不记录姓名、聊天内容、精确位置、身份证件等敏感信息；
- 提供异常存档回滚和内容版本迁移；
- 正式环境、测试环境与测试广告位严格分离。

## 10. 隐私与个人信息

数据最小化方案：

| 数据 | 是否收集 | 用途 | 处理方式 |
|---|---|---|---|
| 游戏进度 | 是 | 继续游戏 | 默认仅保存在本机 |
| 平台匿名标识 | 可选 | 云存档 | 玩家主动启用云存档后才处理 |
| 头像、昵称 | 否 | 无必要 | 不申请 |
| 手机号 | 否 | 无必要 | 不申请 |
| 定位、通讯录 | 否 | 无必要 | 不申请 |
| 设备与崩溃信息 | 最小化 | 稳定性 | 去标识、限期保存 |
| 广告相关数据 | 平台处理 | 广告展示 | 按平台规则在隐私文件中披露 |

上线要求：

- 在调用涉及个人信息的接口之前展示清晰告知并取得所需同意；
- 隐私政策逐项列明数据类型、目的、保存期限、第三方和删除方式；
- 拒绝非必要授权不影响基础游戏；
- 设置页提供数据删除、撤回同意、投诉和联系方式；
- 隐私政策、后台申报与代码实际调用必须一致；
- 未成年人相关信息按更严格标准处理。

## 11. 内容与知识产权生产规范

### 11.1 原创隔离制度

- 不反编译、抓包、解包或复制其他游戏资源；
- 不抄录参考游戏事件，即使替换少量词语也不得使用；
- 不依据截图复刻页面；设计稿必须从本文的信息架构重新创作；
- 每条文案记录作者、版本、资料来源和审核人；
- 第三方字体、音乐、音效、插画和插件必须保存商用授权证明；
- AI 生成素材必须经过人工审查、相似性检查和权利来源记录，不能直接使用带水印或疑似模仿特定作者的内容；
- 宣传中不得使用“某某游戏小程序版”“官方移植”“同款”等造成关联误认的表达。

### 11.2 内容审核清单

每条事件至少检查：政治与机关形象、违法犯罪方法、暴力血腥、色情低俗、赌博抽奖、迷信、歧视、未成年人、隐私、真实人物和地名、广告法绝对化用语、第三方著作权与商标。

涉及法律、医疗、财务、灾害等专业内容时，只呈现概括性的虚构情境，不提供现实建议；必要时由对应专业人员复核。

## 12. 数据指标与验收标准

### 12.1 核心指标

- 新用户完成首个事件 ≥ 80%；
- 新用户完成首局 ≥ 45%；
- 次日留存目标 ≥ 25%，七日留存目标 ≥ 8%；
- 首三局普通事件重复率 < 30%；
- 晋升结果原因查看后的相关差评率持续下降；
- 激励视频主动播放完成率用于优化，但不能以提高次数为唯一产品目标；
- 崩溃率 < 0.3%，存档丢失率 < 0.1%。

以上为产品目标，不构成收入承诺。上线前 200 名测试用户中，若“事件重复”或“结果不透明”任一问题反馈超过 15%，不得进入商业发布。

### 12.2 MVP 完成定义

- 8 个原创岗位、160 条原创事件、12 个结局全部可达；
- 一局可从入职完整运行至结局，存档、恢复和版本迁移通过测试；
- 晋升计算有单元测试，所有结果能正确解释；
- 低端真机、常见屏幕比例和弱网环境通过测试；
- 无充值、无玩家交易、无强制分享；
- 隐私扫描结果与申报一致；
- 所有素材有权属台账，全部内容完成双人复核；
- G0—G7 合规闸门全部有书面证据或平台记录。

## 14. 决策顺序

接下来严格按以下顺序推进：

1. 在微信公众平台创建或确认个人小游戏主体，核对类目和发布材料；
2. 向平台客服及属地主管部门确认本作广告运营需要的游戏审批、备案和主体条件，留存书面回复；
3. 完成《一纸履历》的商标近似检索和微信名称占用检查；
4. 只制作 20 条事件的无广告内部原型，验证玩法；
5. 通过测试后再申请软著，并保证名称一致；
6. 补齐至 160 条事件，进行内容与隐私审计；
7. 取得全部必要编号或批准后，接入正式广告并提交审核；
8. 小流量发布，依据留存和投诉数据决定是否继续投入。

如果第 1—3 步确认个人主体不能合法完成发布与广告运营，则停止面向公众发布，选择合格企业或出版运营合作方；不继续投入完整内容成本。

## 15. 主要风险

| 风险 | 概率/影响 | 应对 |
|---|---|---|
| 个人主体资质不足 | 高/高 | 先完成 G0—G2，再扩充内容 |
| 题材被误解为现实机关模拟 | 中/高 | 全架空岗位、视觉和制度；专业内容复核 |
| 与参考产品过度相似 | 中/高 | 原创隔离制度、设计差异审查、素材台账 |
| 内容重复导致留存差 | 高/高 | 岗位独立事件池、故事链和重复率测试 |
| 广告破坏口碑 | 高/中 | 仅自愿激励、次数封顶、不售晋升概率 |
| 审核规则更新 | 中/高 | 开发前、送审前、上线前各复核一次 |
| 收益不足 | 高/中 | 先用 20 条事件原型验证完成率和复玩，再投入完整内容 |
