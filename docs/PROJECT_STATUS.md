# 项目状态与阶段闸门

更新时间：2026-09-17。产品基线为 PRD V4：《重生之我是公务员的一生》；城市人物虚构，行政层次使用通用名称。

## 2026-09-17：接手审计与技术加固

本轮从参考基线 `e07fd1e` 接管，远程无后续提交。先复现基线：`npm run check` 135 项测试全部通过（含本轮新增 2 项），`npm run simulate` 1,900 局、9/9 结局可达、单局事件重复率 0。

- 修复事件页长标题在小屏横向溢出：原先标题按单行 23px 绘制，320px 下多条标题越出卡片和屏幕（最严重约 99px）。现按长度缩放并换行，卡片高度随标题行数增长。设备矩阵原先只覆盖年度档案和任职弹窗，未覆盖事件页；已补一项测试，把全部 176 条故事在 7 种逻辑尺寸下逐一渲染，断言文字与按钮均不出界、标题完整。
- 新增前后台与尺寸变化的生命周期处理：平台层新增可选 `onShow/onHide/onWindowResize`，界面在回前台或安全区/窗口变化时重新读取尺寸并重绘，滚动位置按新视口收敛，被打断的手势不再误触按钮。本机预览适配层同步接入，浏览器试玩会走到同一条路径。缺这些钩子的旧基础库、预览替身和测试替身保持无操作，不改变原有行为。
- 把“省级及以上岗位不抽基层执行事项”的白名单规则提为显式导出的 `outOfPostScope()`，并让 `scripts/validate-content.js` 复用它列出数据与规则不一致的事件。
- 发现并记录（未擅自改动行为）：14 条工作/区域事件把 `roleLevels` 写到 7—10 级，但 id 不在白名单内，因此在省级及以上岗位永远抽不到。其中巡视、审计、匿名举报、直播外泄等题材按常理适合高岗位，属于“已创作但抽不到”，需要一次内容决定。
- 修正文档指标漂移：README 与平衡审计原写“18 种策略、1,800 局、跨周目重复率约 42.3%—45.6%”，实际为 19 种策略、1,900 局、30.3%—37.0%。

本轮改动为技术加固，不新增事件、不改变数值、事件池或晋升机制；重跑模拟后除源码指纹外审计结果逐字节一致。
