# 发布操作手册（可复现）

本手册给出两条真实可复现的上传路径。**本仓库的云端沙箱不具备正式 AppID、代码上传密钥和微信开发者工具，因此以下步骤需要你在本机执行。** 我不会假装已经上传或提审。

在上传之前，必须先读完 `docs/G0-主体与账号核验.md`、`docs/RELEASE_CHECKLIST.md` 和 `docs/HANDOVER-2026-09-17.md` 的第 4 节。

---

## 0. 每次上传前的固定动作

```bash
npm run check      # 必须 135 项全绿
npm run simulate   # 改动过 src/ 后必须重跑，刷新源码指纹
git status --short # 确认没有把密钥、project.private.config.json 带进来
```

确认仓库根目录**不存在** `project.private.config.json`、`.env`、`*.key`、`*.pem`、试玩二维码。这些已在 `.gitignore` 中，但提交前仍要看一眼。

---

## 1. 路径 A：微信开发者工具（首次发布推荐）

1. 安装最新版微信开发者工具，登录**正式小游戏账号**。
2. 「导入项目」→ 目录选择本仓库根目录 → 类型选「小游戏」。
3. 把 `project.config.json` 里的 `appid` 改为**你确认过的正式 AppID**（当前值 `wxaa230e0fddc4f8c6` 未经确认，不要直接当正式号用）。
4. 打开「详情 → 本地设置」，确认：
   - `compileType` 为 `game`；
   - 基础库版本不高于后台允许的版本；
   - 调试器 Console 中**没有网络请求、没有隐私接口调用**。
5. 用「真机调试」在**苹果和安卓真机**上逐项验收：首屏、事件页滚动、选项点击、翻年、任职弹窗、结局页、切后台再回前台、断网、存储不足提示、存档恢复。
6. 「上传」→ 填写版本号与项目备注（备注要写清本次改动，便于审核与回滚定位）。
7. 到微信公众平台「版本管理」提交审核。

## 2. 路径 B：命令行上传（适合反复发布）

需要 `miniprogram-ci` 与平台生成的**代码上传密钥**。

```bash
# 在仓库外任意目录安装，不要污染项目依赖
npm i -g miniprogram-ci   # 或本地安装后 npx miniprogram-ci

miniprogram-ci upload \
  --project-path /绝对路径/reborn-civil-servant-life \
  --appid <正式AppID> \
  --private-key-path /安全位置/private.<正式AppID>.key \
  --upload-version 0.1.0 \
  --upload-desc "本次改动摘要" \
  --robot 1
```

**密钥来源**：微信公众平台 → 开发 → 开发设置 → 小程序代码上传密钥。密钥必须放在**不在仓库内**的位置，绝不能提交。`--robot` 取 1—30。

沙箱内没有安装 `miniprogram-ci`，也没有密钥，因此这条命令**没有在本轮执行过**。

## 3. 分阶段放量与回滚

`RELEASE_CHECKLIST.md` 要求 5% / 20% / 50% / 100% 分阶段放量并准备回滚方案：

- 灰度期间每天看：崩溃率、次日留存、卡在某一年无法继续的反馈。
- 若出现**推进不下去**的反馈，第一时间取该玩家的存档（本地存档，需玩家截图/描述所在年份与岗位），据此定位是内容耗尽还是状态异常。
- 回滚 = 在「版本管理」中切回上一个线上版本；不要靠热更新替换内容绕过审核。

## 4. 广告接入的前置条件（通过后再做，不要提前接）

1. 正式账号开通**流量主**资格（个人主体门槛与结算方式以你后台实际显示为准）。
2. 在后台拿到**真实广告位 ID**。
3. 只接微信官方能力（如激励视频），保持：**完全自愿、奖励明确、每日次数封顶、不打断主线**。
4. 广告开关要做成可远程关闭（或至少发版可控），并准备投诉与紧急关闭流程。
5. 未成年人广告限制按平台当时的实际要求配置。

当前代码**没有任何广告代码**，这是正确的。上广告时应新增独立模块并补测试，不要动主线存档结构。
