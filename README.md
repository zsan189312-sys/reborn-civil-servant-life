# 重生之我是公务员的一生

《重生之我是公务员的一生》（拟用名）是一款文字选择型微信小游戏。城市、人物与剧情虚构，领导职务层次采用通用名称；从科员起步，体验调任、职级发展与人生取舍。当前版本是**内部玩法原型**，未接入广告、支付、登录、云存档或任何非必要个人信息接口。

## 立即在本机试玩

```bash
npm run preview
```

打开 `http://127.0.0.1:4173`。可切换三种屏幕尺寸，鼠标拖动或滚轮查看被遮住的内容。试玩复用小游戏的同一份引擎和 Canvas 界面，存档仅保存在本浏览器。入口仅绑定本机地址，未公开发布。

这只是浏览器内的微信能力替身，不能证明微信基础库、胶囊安全区、广告或真机性能已通过验证。当前自动布局矩阵覆盖 320×568、360×800、375×667、390×844、393×852、412×915 和 430×932 七种逻辑尺寸及安全区；它能拦截横向越界和按钮溢出，但仍不能替代微信开发者工具、苹果真机和安卓真机验收。

当前有 176 条原型内容：135 条工作、26 条生活、7 条区域、5 条廉洁考察，以及 3 条仅用于读取旧存档的旧版晋升考察模板。新开局不会再触发旧模板。多部门冲突剧情覆盖红包、宴请、采购招标、亲属打探案情、农业直播、食品安全、自然资源、水利林业、科技数据、项目审计、生态监测、交通保通、教育卫生和公共文化；每个选择都有明确后果，但不提供干预案件或规避监督的方法。

默认采用快节奏叙事：每个服务年度只处理 1 个主故事，最多 28 个服务年度。普通年份以岗位故事为主，生活约每 3 年、区域约每 5 年轮入；因果后续和子女节点优先。任职门槛合计压缩为 13 个游戏年。事件页只显示精简正文，完整结果仍写入履历。

去重采用两层规则：具体故事在同一局永久只出现一次；另将案情请托、礼品宴请、项目采购、档案数据、应急安全等语义主题记录进履历，普通独立故事会避开近 3 年已经出现的主题。因果后续可以优先出现，因为它是在回答旧选择而非重新讲同一件事。极端情况下读完当前岗位全部内容，系统直接进入年终评定，不复活旧故事。

履历覆盖党政办公室、民政、乡镇政府、市场监管、政法、公安、发展改革、生态环境、交通运输、省政府综合分工及国家层面的虚构综合协调岗位。青禾、云岑、澄川、栖原均为虚构地区；跨部门资格和任职程序被游戏化压缩，不代表现实可直接调任。综合管理类职级独立记录，不自动获得领导职权。

9 个主结局均有正常开局的可重放路径；违纪处分与刑事判决分开记录，虚构刑期不构成现实量刑说明。176 条内容的双人审核仍未完成；自动校验只能验证逻辑与格式，不能替代人工合规审核。

从最早的架空职业原型切换为公务员路线时采用了独立存档键，旧原型数据仍保留原处。已有公务员路线存档可直接接上此次人生经营更新，无须重开；只根据已记录的生活事件推导住房和伴侣状态，不凭空补出购车、置业或婚姻。

开局、继续存档和进入新年度时，默认显示深色年度档案。首屏按“身份与任期—六项核心状态—年度工作—可选人生安排—人事动态”排序；账本及财务、房车、健康、任职、生活和故事履历收进下半区。长职务名会按屏宽缩放，320×568 小屏仍能直接看到核心入口。任职变化时叠加前后岗位对照弹窗。

每年工作事件选择前可自愿做一次安排：认识伴侣、组建家庭、迎接孩子、两地团聚、购车、置业或休整。购车需现金足够；置业优先抵扣已到账公积金，差额付现金，确认时列明两部分。均一次性付清，之后每年支出会改变；无贷款或交易。所有金额为万元游戏资金，不是现实价格和待遇标准。更复杂家庭玩法尚未实现。

子女原型：成家后的下一年度起，可自愿迎接一个小名“小满”的孩子。本版最多一人，一次性准备费 3 万；从迎接当年起至游戏年龄 17 岁，年度支出另含 2 万，18 岁起停止固定扣款。均为简化玩法，不是现实生育、抚养责任或费用规定。孩子随年度成长；6—9、12—15、18—22 岁各有一段优先触发、单局一次的原创生活故事。旧存档不推断或补出孩子，不操作就维持原家庭状态。

「04 财务账户」可切换查看公积金和职业年金余额、年度预计入账及分页流水。游戏中每次年末结算额外记入当年模拟薪资的 20% 和 10%，不从现金工资另扣；不是现实缴存比例或待遇规定。公积金仅可抵扣自住房购置，年金暂只累计展示、不提供领取或收益，两者均不能充值、提现或用于购车。旧存档不补记历史年份，旧版已生成的年度考核沿用原结算；结局保留账户，不自动兑换现金。

人生安排在年度工作期间随时可选，每年最多一次，也可以完全跳过且不会自动弹出。处理完当年唯一的主故事后，界面直接进入年度履职报告，不再显示“进入年终总结”按钮；系统同时按任职年限、能力、政绩、廉洁、健康、岗位空缺与竞争评价自动作出提拔、交流、留任、职级晋升或降任。

“晋升风声”是每年一次的可选冲突：玩家可以正常汇报，也可以赴饭局或送礼请托。后两者会扣除游戏现金、损害廉洁，并按往年次数累积核查风险；若暂未被查，可能带来短期评价影响，但从不保证晋升，最终仍受硬性条件、岗位空缺和竞争结果约束。该玩法是虚构的道德与法律风险叙事，不宣称现实中请客送礼必然获得职务，也不提供规避监督的方法。

新增三条原创利益抉择长线，占当前事件总量不足 15%：县级老同学以酒和转账请托项目、市级合作方安排“没人谈项目”的饭局、省级亲属争取分包机会。拒绝、披露或回避会承担友情、家庭和进度代价；收受、关照或隐瞒可能短期获利，但会触发复核、退回、信任损失乃至提前结束。事件只呈现冲突和后果，不提供规避监管的方法；界面标注“利益抉择 · 虚构剧情”，正式上线前仍需人工内容与分级复核。

执行 `npm run simulate` 可重做 1,800 局离线模拟，并生成 `artifacts/simulation-audit.json`。18 种策略均走正式自动调任流程，9 个结局全部有可重放见证，单局具体事件重复率为 0。连续三局的跨周目重复率仍约 42.3%—45.6%，未达到 PRD 的低于 30% 复玩目标。模拟不是普通玩家留存或概率结论，详见 `docs/BALANCE_AUDIT.md`。

工程目前采用原生 JavaScript + Canvas，无外部运行依赖。与 PRD 中最初的 Cocos/TypeScript 建议不同，详见 `docs/IMPLEMENTATION_DECISIONS.md`。

## 微信开发者工具预览

1. 安装最新版微信开发者工具；
2. 选择“导入项目”，目录选择本仓库；
3. 类型选择“小游戏”；
4. 内部预览可暂用测试 AppID；正式提交前把 `project.config.json` 中的 `touristappid` 替换为本人已认证、类目合规的小游戏 AppID；
5. 打开调试器确认没有网络请求和隐私接口调用；
6. 使用“真机调试”检查常见屏幕尺寸、触摸区域、前后台切换和本地存档。
